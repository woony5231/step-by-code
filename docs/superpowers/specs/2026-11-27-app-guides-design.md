# 앱 사용설명서 — 설계

## 왜
내가 만든 앱을 실제로 써 볼 사람들(가족, 지인, 아이 부모님 등)에게 카톡 링크 하나로 "이렇게 쓰면 돼요"를 보여주려고.

## 목표 / 하지 않을 것
- 목표: 앱마다 블로그 글 1편. 처음 쓰는 사람이 화면 캡처를 보며 순서대로 따라 할 수 있다.
- 하지 않음: 앱 안에 도움말 화면 만들기(나중에 앱에 링크만 다는 건 가능), 개발 이야기·기술 설명.
- 실패로 볼 것: 개발 용어가 섞여 어려운 글, 실제 화면과 다른 캡처, 캡처에 내 실제 위치나 개인 기록이 찍히는 것.

## 방법 (고려한 것)
- **A. 블로그 글** ← 선택. 이 블로그만 고치면 되고, 카톡 공유가 쉽다.
- B. 앱 안 도움말 화면: 두 앱을 각각 고치고 배포해야 하고 블로그에 안 남는다.
- C. 둘 다: A 다음 단계로 미뤄 둠.

## 정한 것
- **대상**: 기차 앱(https://gicha.pages.dev), 또박또박(https://ddobak.pages.dev). 축제 지도는 완성 후 같은 방식으로.
- **새 카테고리** `사용설명서`(주소 `/category/guide/`)를 `src/consts.ts`에 추가.
- **글 파일**: `src/content/blog/guide-gicha.md`, `src/content/blog/guide-ddobak.md`. 머리말은 기존 형식(`category: "사용설명서"`, `tags`에 앱 이름, `draft: false`).
- **글 구성**: 첫머리 "이럴 때 쓰는 앱" 1~2줄과 앱 주소 → `## 1. …` 처럼 할 일 순서대로, 단계마다 캡처 1장 + 설명 1~2줄 → 끝에 "휴대폰 홈 화면에 추가하기"(아이폰 Safari / 안드로이드 Chrome 각각 한 줄).
  - 기차 앱 순서(안): 가까운 역 보기 → 출발·도착 골라 환승 경로 보기 → 역에서 갈아타는 안내 → 예매하러 가기
  - 또박또박 순서(안): 급수 고르기 → 학습 → 시험(앱이 읽어 주면 종이에 쓰기) → 어른이 O/X 채점 → 결과·기록·오답 다시 보기 → 설정(목소리 속도, 테마)
  - 실제 화면을 보고 순서·단계 수(4~6개)를 맞춘다.
- **캡처**: 휴대폰 크기(390×844)로, 실제 배포된 사이트를 찍는다. 위치는 내 실제 위치가 아니라 **서울역 좌표로 고정**한다. 새 브라우저 상태로 찍어서 내 기록이 안 나오게 한다.
- **이미지 위치**: `src/content/blog/guides/<앱>/NN-이름.png`, 글에서 상대 경로로 넣는다(Astro가 자동으로 크기를 줄여 줌).
- **말투**: 존댓말("~하세요"), 개발 용어 없이. 블로그 다른 글(반말 기록체)과 달리 읽는 사람을 위한 안내서라서.
- **연결**: 소개 페이지 "진행 중인 프로젝트"에서 각 앱 이름 옆에 "사용법" 링크.

## 만드는 사람이 정할 것
- 캡처 도구(Playwright 스크립트 등), 이미지 파일 이름, 단계별 문구.
